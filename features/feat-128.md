# feat-128 - TMA pristine shadcn UI migration

## Goal

Replace the earlier custom-primitive migration direction with pristine Base UI/Lyra output from pinned `shadcn@4.18.0` and exact preset `b6G3fhkA4`, while preserving TMA platform and finance behavior.

## Confirmed scope

- Use Base UI with exact preset `b6G3fhkA4` and pinned `shadcn@4.18.0`.
- Keep generated files under `apps/tma/src/components/ui` CLI-owned and untouched by local behavior or styling.
- Restore generated global preset CSS and Geist Mono; remove the system-font override.
- Keep fixed light without a dark root/token override; retain generated dark branches.
- Put `TmaHapticButton`, `NativePicker`, `DatePicker`, and `DataState` outside generated `components/ui`.
- Migrate consumers to upstream Button, Card, Field, Input, Textarea, Label, Badge, Avatar, and ToggleGroup APIs.
- Remove custom UI files and old token/compatibility code only after import and zero-reference gates.
- Retain native pickers, existing DataState behavior, BackButton, safe-area, tab rail, one scroll root, and meaningful haptics.
- Remove all Telegram BottomButton/MainButton usage.

## Non-goals

- Dark mode.
- Replacing native pickers.
- Changing DataState behavior.
- Backend, API, or unrelated TMA behavior changes.
- Generic primitive redesign or local compatibility aliases under `components/ui`.

## Acceptance

- [ ] Pinned Base UI output is generated by `shadcn@4.18.0` from exact preset `b6G3fhkA4`.
- [ ] Files under `apps/tma/src/components/ui` contain only immutable CLI-generated primitives.
- [ ] External `TmaHapticButton` wraps untouched Button output and passes exactly-once enabled/disabled/busy tests.
- [ ] NativePicker, DatePicker, and DataState are outside generated `ui` with behavior intact.
- [ ] All consumers use upstream primitive APIs with layout/domain styling at usage sites.
- [ ] Legacy token/compatibility zero-reference gates pass before deletion.
- [ ] No Telegram BottomButton/MainButton usage remains.
